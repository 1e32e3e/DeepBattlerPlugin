## 后续计划（用户提出，尚未开始）

### 1. 收集社交平台上的“控胜率”阴谋论，并检验它们对模型的影响

目标：把玩家流传的说法整理成可检验的匹配模型，看它们在模拟里会留下什么“指纹”，再和真实数据对照。

建议步骤：

1. **收集**：知乎、B 站、NGA、百度贴吧、小红书、微博、抖音评论区；Reddit（r/leagueoflegends、r/Overwatch、r/CODWarzone、r/hearthstone）、Steam 社区。记录原文、链接、日期、游戏、点赞数。
2. **归类**：例如“连胜后配坑队友”“连败后放水”“新号/回流保护”“氪金影响匹配”“隐藏分低于段位时被压分”“组排惩罚单排”“深夜匹配更差”等。
3. **形式化**：每类写成第三章那样的匹配规则（触发条件 + 对匹配键或分队的改动）。
4. **模拟与指纹**：复用 `code/ch3/` 的框架，比较诚实 Elo 与每种阴谋论机制下的条件胜率、对手评分差、连败分布。
5. **检验**：说明哪些说法在数据上可证伪、需要什么字段（对手和队友的评分、排队时间等）。

### 2. 用户本人的对局数据：估计实力与波动范围

目标：用用户上传的几款游戏的战绩，估计其实力水平、波动幅度（状态起伏、上头）和是否有可检出的连败效应。

建议步骤：

1. 数据格式见 `data/README.md` 与 `data/template_matches.csv`；原始数据放 `data/private/`（默认不入库）。
2. 可导出数据的渠道（需本人账号授权）：英雄联盟/VALORANT（Riot API match-v5，或 OP.GG 等）、Dota 2（OpenDota）、CS2（Leetify、Faceit）、炉石酒馆战棋（HSReplay、Firestone 本地日志）、王者荣耀（王者营地截图需手工录入）。
3. 方法：
   - 基线：独立二项（或名次多项）模型下的胜率/名次与置信区间；
   - 状态空间模型：实力 $s_t$ 随时间游走（卡尔曼滤波/平滑，或 TrueSkill Through Time），估计波动标准差；
   - 两状态隐马尔可夫（“状态好/差”）与“连败触发上头”模型，检验是否显著优于独立基线（似然比、AIC）；
   - 第三章的连败检验（Miller–Sanjurjo 修正）。
4. 输出：个人实力随时间的曲线和置信带、波动幅度、上头效应估计、建议（如连败几局后休息）。
